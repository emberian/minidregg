Decision and destination
------------------------
Objective Bend is its own language. Bend supplies a starting calculus and a useful
historical admitted execution profile; its existing type system, quantities,
termination checker and call-by-value evaluator are not the ceiling. Ember has
explicitly authorized new syntax, typing, recursion and core representations with
stated semantics, metatheory and versioned interpretation.

The destination is members authoring reusable, manipulable modular specifications,
heterogeneous target extensions, final-self open recursion and whole inherited
super computations, laws, reflection and governed evolution on persistent objects.
Specifications remain usable before closure and when their target diverges. A
backend method dictionary, callback trampoline or rightmost signature resolver is
not the reference definition of these semantics. Native current authorization,
funding, effect admission and release remain separate from behavioral correctness.

The new draft reference is Theory/ObjectiveBendOpenRecursion.lean: independent
weak-head call-by-name Steps, lazy mix and computational Fix. Generic Fix returns
its target; reflective prototype conflation is explicit specification × lazy target
construction. Theory/ObjectiveBendDemandMachine.lean is an executable sharing
candidate with suspended/evaluating/cached thunks and exact-state resumption.
These new modules are currently UNCOMPILED and their sharing adequacy, capture
ownership, type safety and effectful extension remain construction obligations.
No BendTT termination or consistency theorem is inherited by the new Fix.

Language contract
-----------------
1. Source packages are immutable artifacts. Retain exact author bytes, named modules and an ordered sealed import graph. Imports resolve by exact artifact/source digest; aliases are scoped and unambiguous. A mutable name such as community/math@latest is resolved before publication into an immutable lock entry; invoking a published method never fetches today's code. Author/repository labels and signatures are provenance separate from computational identity. Comments/source formatting may change the source artifact identity while the existing executable identity stays unchanged.

2. Objective source uses its own parser and elaborator, preserving authored extension bodies, independent self/super/output annotations, requirements, laws and immutable imports. The historical embedded-Bend profile continues using pinned upstream parsing/checking. The source adapter must load only the sealed local package and explicitly pinned trusted library bytes. Arbitrary filesystem traversal, URL/hub import, implicit Base effects, FFI and @unsafe are unavailable during method execution. Compilation and source resolution are separate from invocation. Merely validating a declared import manifest is not proof that the parser used it: retain the actual parser dependency transcript and bind it to exact parsed/elaborated Book bytes.

3. The historical embedded profile admits Book.check-checked closed live entries with BendTT Eval/Walk call-by-value semantics. The new Objective core has independent partial/lazy semantics and must establish its own typing, ownership, sharing and backend refinement; the following Q0/Q1/Q2 description applies only to that historical embedding. Do not substitute Term.wnf checker conversion for runtime semantics. Q0 terms are dead; Q1 live values are affine; Q2 copies only immutable Data. An underapplied case-tree call retains its original reference and normalized argument spine; it is not a partially unfolded function. Rwt evidence is live until a separate erasure/refinement theorem applies. The source check proves facts about the accepted elaborated Book, not source-to-Book or Book-to-native-compiler equivalence.

4. A world method is a pure computation over a kernel-created typed invocation sample and produces a typed Plan. Plan is data: exact read dependencies, typed proposed effects, message envelopes, private return slots, status and canonical charge evidence. No effect handler runs while speculative/private computation explores a branch. The receiving kernel constructs actual effects and checks current grants, revocation, laws, descriptor constraints, target roots, structural source/kind revisions, budget/clock/payer consent, message audience and release authorization. A well-typed program cannot grant itself authority.

5. World references are Data identifying object+kind/schema revision+audience and optional opaque capability references. Copying a reference copies an address, not a right to mutate. Current authorization is resolved on every invocation. Typed quantities cannot express expiry, revocation, fresh law edits or audience transitions alone. Read-only-looking queries must still authenticate complete dependency roots, including current authority and release rules. Missing sample values refuse; they are never silently replaced by zero.

6. Persistent prototypes retain immutable specification identity and a lazy target, with qualified reusable closures and transitively reusable captures. Affine handles and continuations require explicit ownership and cannot become copyable because an environment is serialized. The historical embedded profile restricts reusable captures to its own admitted Data; that restriction does not define all Objective values. Instances retain persistent application state in governed typed world fields. A resident service stores continuations/checkpoints and mailbox cursor as governed state, then resumes through bounded invocations; it is not an ambient native process with inherited host rights. Doors can provide a useful lifecycle adapter, but Nock's special door record is not the conceptual definition of Bend objects.

7. Dynamic method selection, reflective lookup and self/super must resolve exact versions before execution or record the authenticated resolution reads. Prototype method evolution is a governed change of immutable method references plus declared migration. Old method invocations cannot cross a changed kind/source/revocation/audience root without revalidation. Parent ordering and definition revisions belong to type/object evolution; governance composition and authorization are distinct.

ABI and backend identity
------------------------
Keep the existing immutable executable Program record and its ID. Add a source/artifact record pointing to that ID. Never recalculate a historical Nock program ID, receipts, RunClaims or source provenance to make them look language-neutral. A future cosmetic namespace rename must be a byte-preserving API alias, not a wire migration. Existing Nock accepted-history remains re-executable on its exact evaluator semantics profile.

Bend source artifact identity binds complete source modules/imports/entry; elaborated Book bytes; hashes of exact checker, safe elaborator, BendTT kernel, compiler and prelude/library closure; evaluator semantic version; typed input and output codecs; effect ABI; disclosure/release schema; arithmetic; canonical charging; public resource bounds; backend specialization/version. Store actual hash values, not a flag saying checked. Artifact IDs and backend cache keys differ when any such interpretation changes.

Use one method-level Plan ABI independent of execution profile. Expected result equivalence includes exact canonical effect/message/private-return bytes, dependency sets, final status, and canonical charge; matching one displayed scalar is insufficient. Execution modes:

* Native C/JS: normal author iteration and efficient runtime proposal. Use upstream fast compiler where domain-refinement is proved or independently checked. The kernel still admits the exact intent at current world state. Native compilation is not automatically proved by BendTT.
* Checked kernel: exact reference/verified machine run and canonical codec validation. This supplies referee semantics and metering.
* Oblivious: same typed Plan semantics on concealed bounded working set; keep all authenticated dependencies and hide private branch access/step/output shapes according to disclosure profile. A private branch must not emit host IO, a public address trace or a public branch-dependent refund.
* zkVM: proof statement binds exact program/profile/sample/preimage commitments, private generation/revision, bounds and canonical Plan/charge. Proving a different convenient runtime does not establish this contract.
* Specialized circuit: a compilation/refinement from the same exact method entry and input domain; AIR/proof verifier must bind actual outputs and canonical cost. A generic backend descriptor theorem is not a proof verification path.

Canonical gas cannot be the number of backend physical instructions. Upstream comp.ts drops unused live let values and erases Rwt evidence, so exact optimized-native/BendTT microstep equality is false. Choose a source machine charging law, and prove native/circuit blocks preserve result plus canonical cost or approved canonical upper bound. Existing Nock exact signed steps and fees remain its own semantic profile. Exhaustion, native arithmetic overflow, semantic stuck/crash, malformed input/output, stale state and denied authority are separate outcomes; exhaustion is not evidence of semantic failure.

Bend's native Nat is capped at 2^48-1 while structural BendTT Nat is unbounded. A native Nat48 profile needs a proven bounded domain/fail-stop behavior, not silent saturation. F32 needs explicit bit encoding/NaN policy and deterministic operations; host libm/GPU fast math is not a portable proof of equality. First world methods can use structural labels/bytes and bounded integers while full backend arithmetic refinement is developed; this does not shrink the source language ambition.

Typed world effects and private return
-------------------------------------
The long-term Plan ABI is a sum of typed actions: create/change/erase field value, create/evolve definition, publish/instantiate prototype, send ordered durable message, authorize requested release and return typed value. Addresses include target index, field meaning+codec and key; byte payloads retain their canonical lengths. No scalar cast hides a byte or erase action. Outputs must correspond one-to-one to actual proposed actions; no duplicated aliases exploit set-like equality checks.

Read dependencies include explicit reads and every authority/source/schema/budget/audience read used by actual admission. A guard consumed by a write survives through expectedPre. Private computation may keep the full dependency footprint inside committed private custody while publishing only the approved scope envelope; absent a complete-footprint certificate, do not optimize it to the visible reads.

Messages are part of the atomic admitted successor, with exact sender/recipient capability references, payload schema, sequence/idempotence, delivery/read authorization and durable outbox custody. Sending a message does not synchronously run arbitrary recipient code inside the sender's grant. Replies are fresh governed invocations or private returns. Async orchestration can compose them explicitly without inventing ambient reentrancy.

Private returns need their own declared slots independent of effects. Commit their schema/value/audience into the exact admitted result; release only through current release admission. No conversion of an accepted private result into a public debug log, speculative browser promise or receipt preimage. Authorized inspector view can open a return; other participants get only the contracted commitment/envelope. The current RunClaim.outputJam/effect adapter lacks this independent receiving path, so it is a remaining integration obligation.
