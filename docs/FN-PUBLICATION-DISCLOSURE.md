## What the current R discloses

`FnEvidence.exportPackage` opens the verified origin Store, selects the exact signed call's historical receipt, and encodes `image.seed` plus **every accepted record through `receipt.acceptedCount`**. The package also contains the domain, semantics, genesis pin, exact signed call, and original receipt. `DurableReceiverCodec` preserves the seed's absent bytes, every seed cell's canonical bytes and available budget, then each accepted record's transaction ID, writes (including `canonicalPostBytes`), read guards, nullifiers (including canonical bytes), ten-lane charge, and event envelope (including canonical bytes). This is the entire **original accepted prefix**, not merely the named publication and not later Store history. An unrelated resource's content in that genesis or prefix is present in the evidence. The portable v2 limits (786,432 prefix bytes; 1,048,576 package bytes) refuse an oversized prefix; they do not redact it. `FnEvidence.verify` replays those exact bytes, checks the receipt at the prefix tip, and redoes exact-call lookup. Its present verification claim depends on carrying the full prefix.

`GrainOriginSource.render` checks that the signed call contains the selected settled grain, unchanged parent witness, and a nonempty publication to the named target. It then base64-encodes **all** package bytes into the R MIME body. Selection establishes which accepted operation R describes; it does not filter the package. Fn hybrid signing and Store admission are separate subsequent acts. After public fn sharing, a recipient with R can decode its full Mini prefix. `FnInboxView` presents a summary of the origin package rather than dumping `acceptedPrefix` in its JSON, but the B binding retains `binding.package` and the portable inbox retains the exact carrier in the signed resource view. The summary is not a confidentiality boundary; access to the retained B resource remains governed by B's native observe authority.

The published r5 example is concrete: [`7003-package.bin`](evidence/2026-09-26-hermes-grain-origin/7003-package.bin) is 139,470 bytes at accepted count 10, and [`R.source`](evidence/2026-09-26-hermes-grain-origin/R.source) is 191,283 bytes with that package as base64. The [origin evidence](evidence/2026-09-26-hermes-grain-origin/README.md) names grain 7102, parent 7101 and publication 7003 in one A deployment. This establishes the disclosure shape, not that any particular earlier payload was private. The newer A and B fixtures have distinct Mini Stores and genesis bytes; that separation prevents B's own history from being included in **A's** exported prefix. It does not separate the parent, tool and publication histories already sharing A's origin Store. Separate fn Stores are transport/admission isolation, not selective Mini evidence.

## Present operator boundary

`minidregg-host CONFIG export-evidence CALL PACKAGE` and `mini export-evidence` use a locally chosen config, Store access and exact signed call. Export requires the operator's physical custody of those inputs, but `FnEvidence.exportPackage` checks no new signed observe grant or publication consent. The R author selects the article context, group and named targets; fn sign/post is a further deliberate action. The A-side `FnOriginOutbox` gateway retains and binds an already authored exact carrier to local native verification before posting; it does not narrow what the carrier reveals. These are real custody and signing steps, but they are not a semantic authorization for automatically exporting all earlier same-Store history. A hosted service that holds both Store access and fn credentials must not infer such consent from a request to publish one workroom item.

## Construction choices

An explicitly **public-history origin Store** can use today's native-prefix profile if its genesis and every accepted record up to a chosen receipt are intended for the selected audience. A dedicated Store per publication or grain reduces the prefix to that Store's history; this is isolation by construction, not selective projection. The current r5 origin is not such a per-grain Store. Merely copying a private result into a fresh public Store gives a verifiable public-Store event, but today's verifier does **not** prove that event came from an admitted private-Store operation. `FnOriginOutbox` re-admits the package against its selected origin config, and `NativeReserveContinuity` checks a suffix of one verifier-minted image; neither establishes a cross-Store relation.

For private hosted workrooms that need publicly verifiable linkage to a private source, the missing core seam is an **authorized release certificate or selective origin proof**. It must bind the private deployment and exact accepted receipt/call (or an authenticated commitment to them), the released publication bytes and target, and the public Store event, while keeping unrelated private seed and records out of R. A signed operator assertion could implement a weaker, explicitly operator-attested claim; it would not be independent Mini historical re-admission. A stronger native claim needs a new commitment/proof and verifier contract for selected history or a verified cross-Store release transition. The current flat full-image prefix verifier supplies neither, so a separate public Store alone cannot preserve the present origin claim.

Before any automatic sign/post interface uses today's profile, it needs a **durable, checkable authorization for whole-prefix publication**: identify the origin deployment/Store and receipt, exact package or prefix digest, destination audience/group and carrier, and an authority that may consent to disclosure of *all* genesis and prior records in that prefix. The interface should verify this scope before making the carrier public and retain the exact authorization with its outbox attempt. A selector for one publication target, an observe grant for one B resource, or a warning string is insufficient. If the operator cannot authorize whole-prefix disclosure, the interface must wait for the selective/cross-Store construction and make no native-prefix-publication claim.
