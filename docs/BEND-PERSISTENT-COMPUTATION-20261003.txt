OBJECTIVE BEND — PERSISTENT COMPUTATION CONSTRUCTION, 2026-10-03
Construction status and implementation boundaries are stated below.

DECISION AND PURPOSE
Persist the actual running Bend activity, not just its user data or an app-specific
saga description. The existing Mini native transactional store is the persistence
implementation. Program authors should receive generated continuation capture,
retry and post-durability machinery, while still specifying meaningful atomic
sections, effects, domains and authority. Do not replace the store or pretend that
domain-crossing consistency follows from local checkpointing.

Primary references:
 https://fare.tunes.org/files/fci2017/fci.html
 https://github.com/mighty-gerbils/gerbil-persist/blob/master/persist.md
FCI's observability concerns recovering an abstract computation from an interrupted
concrete implementation through bounded administrative synchronization; a category
of state transitions alone is not a construction. The persistence model explicitly
permits transactional storage underneath while moving persistence coordination
out of ordinary application code. It preserves control stacks and lexical/effect
contexts, separates persistence from publication, and requires durable barriers
and idempotent messages for interactions with persistent peers.

OBSERVATION AND SAFE POINTS
At the explicit pure reference-machine boundary every State is a complete concrete
checkpoint: suspend performs no source transition and needs no I/O. The source
interpretation is richer than a source expression: runtime frames omit some dead
motives, so Simulation.StateDenotes uses relational ghost contexts and exact Book.
Theory/BendClosureSimulation defines StateDenotes, source Trace/count relations,
ReadyPointer and DataCacheSound; whole-controller reachability remains a separate proof. Restoring equal actual State preserves those facts.
Refused states need the separately retained pre-failure source prefix; absence of
StateDenotes for refused does not justify inventing a residual source term.

A native CPU interrupted inside the implementation of step is NOT automatically
at that boundary. Proposed concrete worker protocol keeps a strongly held,
immutable published input-State and constructs a private successor; only a
completed pure step is published. An observation request can select the last
published State without waiting for external I/O or completing source evaluation.
Any discarded unpublished pure work is recomputable and has no external effects.
The implementation must establish object lifetime/refcount aliasing, publication
ordering, bounded administrative access, and absence of effectful callbacks inside
step. These obligations are OPEN: a Lean value and run_add are not a proof about
native CPU registers, allocator interruption, fsync, or another language runtime.

Further source-level observation at a desired abstraction boundary uses the
controller simulation invariant, not a runtime source oracle. Bounded stuttering
and adequate capacity establish how much administrative work is necessary. A
pause request may not wait until a whole long source computation terminates.

EFFECT CONTINUATIONS: NEXT JOIN, NOT CLAIMED COMPLETE
Generated activity state should hold one of: computing exact machine state;
prepared typed Plan and exact continuation; awaiting its native admitted outcome;
ready to continue with the independently typed result; terminal/refused. This is
one activity record in Mini's store. There must be no second private app journal.

1. Compile source effect suspension into an explicit finite continuation/context.
   Proposed source ABI is an affine pair of typed Plan data and captured
   continuation closure, using actual Row.pair/closure/env. The result injection
   codec must prove typed bounded Data reification before applying that closure;
   the current Plan bytes ABI alone does not encode this continuation. Exact
   generation consumption must prevent duplicate scheduling after retry/restore.
   Retain exact current input/support manifest and Plan/Return ABI. Current pure
   closure machine has no arbitrary host effect primitive; do not pretend it does.
2. Native source admission commits checkpoint + exact Plan intent identity +
   pending outcome/continuation and supporting reservations atomically. A Plan
   is still checked against current capabilities/policies/fees/read guards.
3. Only after actual durable source record/readback may the dispatcher expose an
   effect or send a message. Merely accepting transport custody is not this barrier.
4. Retry the same exact intent/dispatch identity; retain uncertainty after an
   ambiguous external effect. Resolve using authoritative native lookup/outcome,
   never bounded-feed absence or a new request with a fresh identity.
5. Persist the acknowledged result and new continuation before retiring old
   obligations. Release independent private results only to currently authorized
   audiences. Restoration does not resurrect revoked authority.

Captured provider context is immutable for an already-started invocation. Future
inference reloads current signed projections; source edit/move/revoke invalidates
dependent summaries. Kernel/ResidentContextProjection supplies the context/support
manifest boundary; already-started provider context must remain immutable.
A legacy SPK app process remains a transient/external adapter: its pending request
and dispatch journal do not capture its stack/heap/OS context. It needs its own
restartable protocol or actual execution-context capture to join this guarantee.

METACONTROL AND MIGRATION
Inspection, suspend/resume scheduling, cancellation, checkpoint export and changing
implementation are separate capabilities from ordinary object methods. Authority
to invoke a method does not entail authority to dump its private heap. Current
source access/release must govern snapshot inspection and portable artifact export.
Metacontroller actions retain their own audit identity and limits; an object may
expose explicitly delegated inspection without surrendering mutation authority.

Version1 resumes the SAME exact operational context and generation. No metadata
flag permits native->FHE, MPC->clear, or arbitrary code migration. A change requires
an actual state translation preserving the source residual/continuation semantics,
authorized effects, leakage/custody, resource contract and pending obligations.
For the same semantics different implementation, old/new source interpretations
must meet at an admitted safe point; for evolution changing desired behavior, a
separate authorized migration law names the permitted change. Source rows, method
identity and persistent activity identity must not be conflated.

Retained old checkpoint execution must be fenced by current native generation/
worker custody. Canonical bytes and generation equality alone cannot stop two
workers: restore is deliberately pure and repeatable. The actual Activity phase
CAS must consume exact predecessor+generation, and both continuation advance and
post-durability dispatch authorization must bind the same consumed transition and
intent ID. External peers still need deduplication/uncertainty handling. Domain transfer
requires actual source decision/private qualification/old-worker fence; portable
manifest readiness is not an execution permit. Cross-domain effects still consume
the real agreement/reservation construction. Resource refusal preserves state and
repair capacity; storage GC must preserve all pending messages/claims and retained
continuation dependencies, not merely the most recent user-visible document.
