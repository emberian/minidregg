# Generic Objective Bend typed preview

`objective-front preview REQUEST_JSON OWNED_EMPTY_OUTPUT_DIR` (the Lean front end, `Host/ObjectiveBendFrontEnd`: `lake env lean --run Host/ObjectiveBendFrontEndMain.lean preview ...`, or the native Host's `minidregg-host /dev/null objective-front preview ...`) consumes an immutable captured package (`objective-front capture`). Studio pins the native Host binary, so the parser, elaborator, checker and machine it runs are the ones compiled into that binary; the result's `binding.frontEnd` names the front-end identity, which must equal the capture's. Browser clients must supply capture identifiers through the Studio capture service; they cannot select filesystem or tooling paths.

The request schema is `dregg.objective-bend.preview-input.v2`: `capturePath`, its exact `captureSha256`, `arguments` (canonical decimal Nat strings, Booleans or recursive records), `projections` (`{field,argument?}`), and `limits` with positive canonical decimal strings `ticks`, `heap`, `stack` (each at most 100000) and `typeFuel` (at most 16384). The capture retains the original request hash and every source and import fingerprint, and names the front end that made it (a capture made by another front end refuses). The preview re-reads and re-checks the exact retained source, parses it and emits the actual de Bruijn core. It never substitutes an example Book or result.

The front end emits a core packet and the annotation proposal (one term, rendered once). `Host/ObjectiveBendPreview.lean` decodes that proposal, invokes the actual proof-producing annotated checker, and only on acceptance executes `runBounded` on that same decoded term. Closed source contexts are required. Bounds affect suspension and are recorded in the result. Source annotation proposal support is narrower than the parser: candidate 1 admits zero-argument literal declarations; candidate 2 proposes explicit Nat and named-record signatures plus captured Extension<Nat> factories. Unsupported annotations produce a diagnostic rather than bypassing the checker. New source signatures can extend that producer without replacing the checker.

Success is `dregg.objective-bend.preview-result.v2`, with `status` (`finished`, `suspended`, `divergent` or runtime `refused`), `binding` (capture/source/core/typed-packet hashes, the front-end identity and requested limits), and `preview` containing the actual type, uses, the weak-head `result`, the deep `resultData` and machine capacity observations. A source/type/tooling refusal uses the same outer schema with `status: refused` and a structured `diagnostic` stage/message; exit status is 2. Machine outcomes are JSON results and exit 0, including honest suspension/divergence. Outputs are created in an empty owned directory and never modify the capture or Studio store.

This is a clear, effect-free preview of the new Objective edition. It does not admit native current observations, affine effects, private ciphertext inputs, law discharge or world receipts. Elaboration adequacy and demand-machine preservation remain independent theorem obligations. The immutable wire-v1 candidate 2 passed actual Studio Nat 8, captured reusable extension Nat 12 and heterogeneous extension Nat 10. Its real Studio consumer also preserves the old capture result while a signed document edit and fresh capture produce Nat 42, and reports an actual Nat/String typing refusal. These are compiler consumers, not native effect admission. The repaired mix capture rule and finite row equality checker are pinned.

The current source now targets runtime wire edition 2: `core.v2` and `typed-core.v3` contain explicit Boolean constructors; `typed-core.v3` names types through a shared table (see [the front end](OBJECTIVE-BEND-FRONTEND.md#typing-proposal)). `typed-preview.v2` requires that exact family. The source AST remains Objective edition 1. String `"true"` stays a String, Boolean `true` is a distinct Boolean result, and String conjunction is refused by the checker. Candidate 1/2 wire-v1 artifacts remain immutable; they are never silently decoded as wire-v2. Wire-v2 candidate 4 passed its coherent receiving cohort against the separately qualified Core4/checker and explicit tagged-argument lowerer: the unchanged Studio source returns Nat 8, a captured reusable extension returns Nat 12, and heterogeneous extension source returns Nat 10. Actual String "true" has String type and label result, Boolean true has Boolean type and result, and String conjunction is refused. An independently authored ScalarAdvance source accepts tagged Nat 7 and the native canonical root String "0bff" and returns its whole typed nested Plan record. A separate demand of its effects."0".after yields Nat 8. The original wire-v1 Studio tooling remains intact until an explicit service edition change.

A public source package manifest is `tests/objective-bend-source/GenericExtension-package.json`. From the source root, run `objective-front capture tests/objective-bend-source/GenericExtension-package.json OWNED_CAPTURE_DIR`, write a `preview-input.v2` request naming `OWNED_CAPTURE_DIR/objective.json`, its `sha256sum` and arguments `["7"]`, and run `objective-front preview` with it and a new result directory (`docs/tutorial/run.ts` does exactly this for one file). The manifest selects the reusable captured extension source; its result for seed 7 is 12.

Wire-v2 requests can select `argumentEncoding: typed-values-v1`. Their `arguments` are explicit `{tag:natural,value:"7"}`, `{tag:label,value:"HEX"}`, `{tag:boolean,value:true}` or recursive `{tag:record,fields:[{name,value}]}` objects. The preview passes the versioned argument-value envelope to the elaborator; String values are never inferred from Nat-looking strings. The separate legacy-values-v1 route retains canonical decimal Nat strings/Boolean/record input. This extension permits actual canonical native digest Strings to enter source methods without rewriting their bodies or confusing them with numbers. Native context authority is still checked by the world receiving adapter independently.

`result` is the weak-head view: a record shows its lazy field names, a sum its label. `resultData` is the deep view: after the run the host forces every field and payload through the machine's own budgeted materialization (`ObjectiveBendDemandData.complete`, the path native extraction uses) with a fresh allowance of `ticks` machine steps, `heap` nodes and 1 MiB of canonical encoding, and prints typed data (`{tag:natural|boolean|label|record|variant,...}`, the same wire as a yielded Plan). A result that is not first-order data (a closure, specification or prototype anywhere inside) or that exhausts the allowance has `resultData: null` and `resultDataStatus` naming the failure (`executableValue`, `suspended`, `budget`, ...), never a partial value; a finished result has `resultDataStatus: "materialized"`. The deep view does not claim that the result has passed the native Plan adapter. Native receiving must demand and validate the complete result. The preview cohort also checks changed-capture identity and type-budget refusal, plus tick and heap suspension with no false source result.
