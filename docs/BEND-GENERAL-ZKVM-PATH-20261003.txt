ENTROPY FINDING AND ITS LIMIT
Bread circuit/src/stark_zk.rs uses SmallRng in both hiding MMCS and hiding FRI.
OS seeding does not turn that generator into a CSPRNG. At this P3 revision,
MerkleTreeHidingMmcs::clone and HidingFriPcs::clone duplicate the RNG state.
The configuration itself clones value MMCS for challenge MMCS, so overlapping
streams are a concrete API/configuration concern. This is a source finding,
not a demonstrated attack against a deployed proof.

P3's hiding MMCS documentation requires a seeded CSPRNG and enough salt
entropy; the generic trait bounds do not enforce either. rand0.10 StdRng
is cryptographic but intentionally not Clone, so a rename alone does not
satisfy the consumer. Shared advancing state addresses that API boundary.
Independent channels plus clone sharing avoid deterministic state copying.
Eight uniform BabyBear salts provide ~247.3 raw bits; this does not imply a
128-bit quantum or composition guarantee. The original four provide ~123.6
raw bits, not128. Poseidon2 capacity, exposed openings, random-codeword count,
proof count, adaptive use, statistical masking and full FRI/PCS reduction
remain distinct. The harness uses IR2 log_blowup6/queries19/queryPoW16,
extension degree exported by actual source; no heuristic bits sum is a proof.

SHORT-TRACE MASKING FALSIFIER / CONFORMANCE REPAIR
Further actual-code reading found a masking obligation independent of RNG:
IR2 passes a one-row main trace unchanged; its minimum-eight-row helper is for
auxiliary tables, not the main trace. HidingFriPcs appends one independent random
row per one real row. BatchSTARK then exposes each trace column at extension-
field zeta. For a one-row trace the committed column is a degree<2 base-field
polynomial a+bX. For non-base zeta, the public opening a+b*zeta uniquely reveals
a and b (1,zeta are base-field-linearly independent), hence the original row.
This is a source-level disclosure argument, not yet a captured live proof.
It survives replacing SmallRng with a CSPRNG or adding more Merkle salts.
