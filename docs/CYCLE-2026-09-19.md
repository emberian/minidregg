# New World construction cycle 1

Ember authorized one substantial implementation-and-integration cycle after selecting Mini as the New World's implementation home. This cycle expands the actual receiving system and measures the integrated result. Bread is reference material; no Bread runtime or new Python platform is a prerequisite.

The implementation target is a signed, persistent multi-resource journey through the compiled `minidregg-host`, with a usable Rust client:

1. Create a task/object and typed content with source-authored laws and owner authority.
2. Delegate a restricted participant right and authorize scoped observation.
3. Change content and task state in one transaction, checking all laws against the actual joint final state.
4. Refuse a transaction with an invalid second leg without publishing the valid first leg.
5. Replace a policy without invalidating grants, and revoke a grant through explicit management authority.
6. Restart and retry the original signed bytes, recovering the original receipt rather than executing twice.
7. Preserve deliberate management lockout and refuse missing, excessive or wrong-kind read authority.

This is one general resource path. Singleton mutations use the same finite transaction receiver. Content payloads are canonical typed bytes, not references to an authoritative host-side database. Native code provides transport, signing, physical storage and process execution; Lean owns command meaning and admission.

## Validation and measurement

Per-file elaboration is iteration evidence. Final integration requires the full `Minidregg` umbrella plus the actual native host, the real public CLI journey, and focused Rust client checks. Test artifacts identify source/configuration and distinguish refusal, uncertainty and successful execution. A source-only construction or historical fixture does not count as this cycle's executed result.

Local Lean compiler concurrency is capped at two with explicit process seats. Full Lake work runs only in an isolated source/artifact snapshot until an integration freeze. Native packages must be copied with independent writable state; current local dependency symlinks are not independent snapshots. Remote work follows the existing memory and storage rules.

Cycle planning began around 18:08 UTC on September 19; the first explicit clock observation was 18:16:09 UTC. Final evidence will report elapsed time, integrated behaviors, checks and remaining work. This document initially records the target, not completion.

The old host profile/wire epoch is deliberately advanced for joint commands, typed content, revocation and observation. This cycle does not claim migration of a deployed old store, distributed finality, full STARK assurance, provider-request notarization, live token operations or complete hosted Hermes deployment. Those remain construction work around the same Mini resource system.
