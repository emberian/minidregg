BEND AUTHORED-DATA REPRESENTATION
Rewritten 2026-10-04. The 2026-10-03 version was a lane receipt for data
representation on the retiring BendTT path; Git history keeps it.

WHAT IS TRUE NOW (Objective Bend Core4)
Core4 has three scalar kinds and records, nothing else:
 - Term.nat n (unbounded Nat), Term.boolean b, Term.label s (opaque string).
 - Term.record fields: lazy fields, first match wins on lookup.
 No sums, lists, bytes, words or case on constructors; the only branch is ifZero
 on a Nat. Booleans have no eliminator (`==` yields one, nothing consumes it).
A finished result leaves the demand machine as a RuntimeValue (closure, scalar,
record of heap addresses, specification, prototype). Theory/ObjectiveBendDemandData
extracts deep first-order Data (natural, boolean, label, record of Data) by
re-entering field addresses, and refuses on budget exhaustion, duplicate fields,
a closure reaching data, or a cycle. Its canonical byte encoding tags each kind
(0 nat as decimal text, 1 bool, 2 label with byte length, then records).
Extraction has unit tests (tests/objective-bend-source/CheckDemandData.lean) but
no soundness theorem relating the extracted Data to the source meaning.

PRINCIPLES THAT CARRY OVER
 - A codec refuses what it cannot represent; it never wraps, truncates or
   saturates. A byte is a Nat < 256 checked before conversion; a word refuses an
   out-of-range value instead of reducing it.
 - Source Nat, bounded native words, field elements and BFV plaintext rings are
   different domains. Every crossing names its bound and its failure.
 - A unary or structural source encoding can be a proof witness without being
   materialized by a native implementation.
 - Source step charge and physical work are separate quantities.

WHAT CORE4 STILL NEEDS HERE
Sums with case, then lists (sums plus records) and bytes as a checked list of
bounded Nat, then a typed Plan ABI that is a sum of actions. Ranked in
docs/OBJECTIVE-BEND.md.
