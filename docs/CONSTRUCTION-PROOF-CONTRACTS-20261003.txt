EVIDENCE RULE
A claim has six parts: implementation function; specification; universally
quantified theorem; explicit premises/axioms; actual consuming path; remaining
implementation join. Keep these evidence kinds separate:
 S = checked semantic theorem over the stated model and all its quantified inputs.
 C = cryptographic theorem/model and concrete assumptions/parameters.
 R = refinement from the actual implementation to S/C (often still missing).
 V = executions, mutation refusals, crash/adversarial validation.
 A passed compilation, example, syntax lint or standard axiom set cannot replace
 S/R. A conditional theorem whose premise is the desired security property does
 not construct that property. A finite Bool theorem proved by constructor cases
 IS general over that finite domain; a successful Bool example alone is not.
