# Lean compilation and qualification

Source-first publication keeps authored work on main. A declared target, an owner report, successful elaboration, a general semantic theorem, and a native receiving result are different facts. The source inventory records hashes and owner reports; it does not manufacture a compiler result.

Use the pinned toolchain and dependencies in `lean-toolchain` and `lake-manifest.json`. On a designated build host, use its resource guardian and one coherent warm namespace. Lake may build missing dependencies: inspect the import closure before a scoped check.

| Target | Purpose | Limits |
| --- | --- | --- |
| `lake build Minidregg` | Stable per-directory roots and previously orphaned carry/recovery gates | Does not claim the authored research tree compiled |
| `lake build BendQualification` | Components of the retiring BendTT stack: source admission, compiled controller regressions, raw circuit execution, arithmetic witness/refinement, natural-expression compiler, compact source binding | Says nothing about Objective Bend Core4. Its Gen-1 import (`Kernel.ObjectiveBendCallContext`) is removed with the Gen-1 cut |
| `lake build ResearchWip` | Opt-in research library; at this revision it is the only target that compiles the Objective Bend Core4 proofs (`Theory/ObjectiveBend*`) | Not part of the default gate; a green `Minidregg` build does not re-check those proofs |
| `lake build SimplexQualification` | Executable causal/history/emission closure, global engine safety and inhabited/hostile witnesses | Consult the theorem hypotheses; native signed participant receiving is a separate consumer |
| `lake build bend-controller-probe` | Synthetic public controller census over the retiring BendTT closure machine | Finite compiled regressions, not general step refinement; not an Objective Bend controller |
| `python3 scripts/lean-build-surfaces.py research` | Remaining authored library modules and standalone program roots | Explicit opt-in; may fail and does not gate ordinary source publication |

`protocol/lean-build-surfaces.json` is generated by `python3 scripts/lean-build-surfaces.py generate`. Its `check` command rejects source drift or unclassified modules. `scripts/check-build-closure.sh` checks declared coverage; compilation is performed by the actual targets above. Research compilation is excluded from the normal gate runner and reported as opt-in. No successful structural scan substitutes for a compiler result.

The four formerly orphaned carry/recovery gate modules are imported by `Minidregg`. `Verify.JointDecisionRecovery` now uses `#assert_axioms`, so nonstandard axioms fail elaboration; bare printing was diagnostic only. Axiom checks constrain trust, not theorem strength. The controller fixture assertions use explicit compiled checks. General statements and their assumptions must still be reviewed.

Import tiers are checked by `scripts/check-import-boundary.sh` (the `import-tiers` gate) over every tracked `.lean` file. Its table carries one deliberate relaxation: commit `76757030` (2026-10-03) let `Theory` and `Kernel` import `Lean`, `Std` and `Init` in addition to Mathlib and the tree's own libraries. The toolchain is not candidate code, but the check is weaker than the 2026-10-01 table it replaced (the metatheory may now import the elaborator), and the script header names it as such. Narrowing it is an edit to that table.

The current evaluator registry remains Nock-only. Bend registration requires the independent specification, soundness, completeness, deterministic/crash/exhaustion laws, stable metering and byte-entry relations in `Compiler/Evaluator.lean`; a reference adapter does not discharge them merely by returning a proof-carrying trace. Native Bend source/Plan admission work remains a separate, unfinished integration.

The dated intake ledger records published source status. Aggregate targets added by this change have not yet received an aggregate compiler PASS. Qualified component snapshots and native receipts remain separate evidence. The modern source tree is not the historical service executable.

To emit the actual imported theorem statements and their axiom footprints, run
`lake env lean scripts/report-bend-qualification.lean` or
`lake env lean scripts/report-simplex-qualification.lean` after building the
matching target. Each `QUALIFICATION_CLAIM` JSON row comes from the elaborated
environment. The emitter labels compiler trust and does not infer premise
inhabitation or hostile witnesses from a name, an axiom scan, or a case count.
