# SPK physical dispatch custody component, 2026-09-27

`native/spk-host/src/hostd.rs` SHA-256 `52b21e5c98485aaea48643d3904f61990920f1b4feaea7f045c953dd1f7cdab6` adds a durable one-shot journal transition before an app fd3 RPC. It is a physical custody primitive, **not** a Mini admission parser or enabled delivery route. The private browser/API entrance still returns 503. The exact native op34 committed-permit route, source-owned inspection, current process/claim checks, and fd3 join remain to be integrated.

Under the same per-app flock as lifecycle start/stop, the journal compares the request's app ID, generation and manager-captured InvocationID to the running app record. It checks the declared SHA-256 and size of the original private op34 success payload, fsyncs an active marker, a mode-0600 exact payload capture, a `DeliveryRequested` tombstone, and then the in-flight record. A crash after the first marker blocks further delivery pending audit. The tombstone filename is a SHA-256 of a length-delimited app/generation/session resource/session generation/operation ID coordinate. Distinct sessions may issue identical HTTP bytes; the same operation coordinate cannot be reused with changed bytes or receipt. The payload digest and native transaction/event stay in the tombstone contents.

The lifecycle lock is released during the app RPC wait so hard stop can fence and kill the exact unit. Completion reacquires the lock and checks the in-flight identity, active marker, captured payload SHA-256, app generation and phase. A reply after a fence or an uncertain RPC leaves the durable operation unresolved and is never automatically resent. A successful completion records `Delivered`, then clears the in-flight marker. This code does not establish that the app was ready or that a reply is semantically accepted by Mini; those checks belong to the later adapter.
