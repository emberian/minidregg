# Private event20 and lifecycle completion authoring routes

This source cut adds private native stdio 40–45 to `Host.Main`. Op40 accepts a strict event20 registration ingress only after querying the operator-pinned local fn consumer position/status and matching its exact scope and control binding. Op41 selects only the original event20 receipt from a verifier-minted history. Op42 takes no caller selectors: it reads the fixed `fnPoll` service's private executable, scope, gateway policy and control endpoint, requires native position and committed ACK both zero, and returns the source-owned framed namespace Plan. Op43 accepts a length-framed pair of that canonical plan and the detached credential envelope, rechecks the local zero position and current Mini gateway roots, law and signing header, then returns the strict event20 ingress. The plan inspector displays canonical bytes and the actual signing header; it grants no authority.

Op44 requires the separately configured `completionManagement` pin and a current verified Mini session. It returns the source-derived completion plan for exact retained BEGIN-v2, claim-v2 and signed physical report bytes. Op45 strict-decodes that plan and detached signature list, then returns canonical event18 ingress. Neither plan path submits work or creates a host launch permit. The new management pin is an exact private Settings object; it never comes from the request frame.

An independent writable Persvati overlay at `/home/ember/build/mini-main-inspect-overlay` serially compiled `FnConsumerNamespaceAdmission`, `FnConsumerNamespaceReceiver`, `FnConsumerNamespacePlan`, and `Host.Main` with direct `lake env lean -o`. All four commands exited 0; their logs are empty. The overlay imported source-matched `ApplicationLifecycleCompletionOperator` and `Host.Json` OLeans from the separately narrow-green completion authoring cut and the committed event20 Replay image. The source and OLean hashes are pinned in adjacent manifests. No native link, fn registration, event20/event18 physical acceptance, POST, or ACK is claimed by this check.

`native/resource-client/src/transport.rs` now admits 40–45 only on the owner-private operator socket. It requires empty op42 input, bounds event20 ingress and pair assembly, and refuses every new route on the public socket. Isolated `cargo nextest` runs passed the new `namespace_and_completion_authoring_routes_stay_private_and_bounded` test and the existing `lifecycle_and_dispatch_routes_are_bounded_and_operator_only` test; `cargo fmt --check` passed. The test output and exact commands are recorded in `transport-verdict.txt`. These tests check broker framing and privacy, not Lean admission semantics.

This first route supports **fixed fnGateway configuration**. `fnGateway` is not part of current `Config.runtimeParameters`; switching its operator pin against an existing Store can make old event20 history fail replay. Same-Store gateway rotation is not qualified. A different gateway requires a separate Mini deployment until historical pin provenance and migration are implemented. Local fn status is point-in-time operational correspondence, not a lease or proof of remote fn completeness. The helper currently authors fresh zero activation only; nonzero legacy adoption is not exposed through op42/43.
