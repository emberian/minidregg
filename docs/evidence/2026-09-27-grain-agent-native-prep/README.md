The protected [config overlay](../../../native/grain-runtime/prepare-agent-controller-configs.sh) adds only explicit `foregroundTool {reserve,charge}` to independently supplied A/B configs after checking the committed allocation's parent/tool/purse/provider identities, same app8401, respective sessions/tickets, and the event22 carrier. It never creates a key, receipt, Store, or authority. The [recipient preflight](../../../native/grain-runtime/agent-two-participant-preflight.sh) still requires exact op55 replay, current signed app/manifest/snapshot/ticket/parent/purse views, and a positive source-authored v2 SPK launch descriptor. It now checks the foreground allowance and four distinct subjects/tasks, plus a fixed `hermes-acp` command. The `script-check.log` records `shellcheck`, `sh -n`, a positive explicit-profile overlay and refusal of a wrong provider subject.

After the SPK owner produces the fresh integrated Store, runs that recipient preflight, starts both protected controllers and resident host routes, the [foreground journey](../../../native/grain-runtime/agent-two-participant-foreground-journey.sh) can run with the exact binary/config and completed preflight evidence. `status-soft-lost` holds the original soft socket until the controller journal durably claims each A/B request ID, then discards its reply and uses read-only `tool-result`; it asserts exact same-byte and changed-byte duplicate refusals, no extra operation allocation, explicit `tool-ack`, and post-ACK result lookup. `api-get` is a separate opt-in stage requiring the source-qualified event21 Host SHA; it sends `GET repo.git/info/refs?service=git-upload-pack` through both fixed `gitweb-app` API sessions and requires HTTP 200, Git advertisement content type and a nonempty body. The scripts do not forge or infer a permit. A `hard-eof-observe` stage captures a hard-close request ID and exits 3 pending operator inspection; it does **not** claim in-flight native cancellation or automatic reconciliation.

The current event21/v2 ticket is parent-generation-bound. A hard generation advance cannot be treated as an API reconnect permit. The planned event26/v3 lifetime-grant route needs its own source-qualified authoring, Host and controller integration before API reconnect acceptance. Hosted unforked Hermes remains a later stage using the config's actual fixed `hermes-acp` command and an explicitly configured deterministic local provider fixture; these scripts neither fake a Hermes session nor spend an unstaged model credential. Exact hard EOF versus in-flight provider effect, fresh generation continuation, and lost API reply recovery remain required native journey checks.
