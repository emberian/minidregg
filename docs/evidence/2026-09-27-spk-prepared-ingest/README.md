# Root prepared GitWeb ingest wrapper (source-only gate)

`deploy/spk-host/spk-ingest-prepared` consumes one completed source-bound materialization request. It first invokes the root-private inbox stage helper. Before any root execution, it checks every component of the root-installed helper and SHA-pinned SPK Host paths for root ownership, no symlink, and no group/world write bit. The existing `spk-ingest` remains the bounded physical materializer. The wrapper fsyncs its operation directories, writes and fsyncs `ingest-requested.json` before the one physical ingest call, then retains the ingest output and runs read-only signed-image inspection in a bounded offline systemd unit. Inspection attempts have separate numbered directories and systemd verdict logs. An already installed exact image is inspected without invoking ingest; a prior request marker with no image refuses a second ingest.

This cut did not execute root ingest or inspect an installed GitWeb image. `bash -n` and ShellCheck passed. The exact executable-custody function passed a private Linux test accepting `/usr/bin/sha256sum` and refusing a task-owned copy and symlink; its output is `custody.log`. The r3 Store and physical SPK paths were not changed. A root-installed qualified SPK Host and accepted r3 INSTALL claim remain prerequisites for a live run.
