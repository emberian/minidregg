# Descriptor-bound lifecycle v2 source gate

The new strict BEGIN v2 carrier includes the full `ApplicationSpkPackageIdentity.Descriptor` preimage. Admission first runs the existing current DRC, policy, signature, package observation, and physical-guard checks against one loaded image. It then requires the descriptor's full validity and bridge mapping, `descriptor.root = source.packageDigest`, and an exact source-derived prospective Mini manifest (app, installation-sequence version, root, ordered interfaces and schemas). For start/stop, that same signed and read-guarded package cell must decode the *currently installed* manifest exactly. Install/upgrade bind the prospective manifest for checked completion; they do not claim it is already installed. The signed upstream SPK `appVersion` is committed inside the descriptor but is separate from Mini's package installation sequence.

Claim v2 repeats the exact descriptor-bound original BEGIN, re-admits it at its original prefix, and compares the complete stored intent. Replay holds a separate private chronological `PriorBeginV2` certificate only after original admission, record equality, durable advance, and post validation; a v1 BEGIN cannot satisfy a v2 claim. Current claim admission still requires today's management law, original mutation capability, signed app/package observations, pending generation, and image boundary. Event families remain allocated 12 and 16 with domain-separated v2 canonical bytes. The v1 ingress/event/receiver remain unchanged for historical replay. `ApplicationLifecycleClaimCore.intentFromCurrent` shares the source-byte-dependent metering implementation across claim versions; the historical v1 event and wire bytes remain unchanged.

The BEGIN v2 receiver records pending work only after exact CAS post-image readback. The claim v2 receiver yields a private one-shot reservation only after the same exact readback. Its strict `DREGG/APPLICATION/LIFECYCLE-CLAIM-COMMITTED/v2` projection includes the complete descriptor, original BEGIN/claim identities, current physical roots, and post-image boundary. `Reservation.projection_valid` proves descriptor validity and root equality; `withFreshTip` rereads exact physical bytes immediately before handoff. Neither receiver attests that a host process started or completed.
