# Native policy-install crash window (task 7705)

A fresh isolated 7705/7706/7707 deployment installed the source-authored parent worker law for generation 1. The policy-install call was confirmed, and the controller journal still held its exact pending attempt. The fixture recorded the owned `mini-grain-controller@7705` description, InvocationID, and MainPID, then sent SIGKILL to that unit's main process before any grain attach source existed. A signed post-crash query showed parent generation 0/status 0 and policy version 1; the policy predicate's canonical bytes matched the authored generation-1 law.

On restart, `recover` used `mini retry --mode lookup` for the retained policy attempt. Its `confirmed/replayed` result has the same transaction ID, event ID, and image boundary as the original `confirmed/installed` result; the original call hash remained unchanged and the pending slot cleared to `Detached`. A later soft attach succeeded with one confirmed grain attach source. Signed parent state became generation 1/status 2/remaining 100/reserved 0. The resulting version-2 policy predicate still has the exact canonical generation-1 bytes. The original policy call was **not resubmitted**; a new versioned policy renewal during the later attach is normal runtime behavior.

This is a **same-deployment continuation** result, not a one-pass runner verdict. Two test-harness errors interrupted the continuation: it first tried a stale socket path before the replacement controller listened, then incorrectly expected lookup confirmation `installed` instead of `replayed`. Those errors caused additional fixture-owned controller stops. The final attachment was made against the same Store, keys, confirmed call, and durable journal. The corrected reusable recipe is [policy-crash-acceptance.sh](../../../../native/grain-runtime/policy-crash-acceptance.sh), SHA-256 `5f476a1370b0b7220d1a3d339cc1876db5a2e1509e8489085062c43e897a8f3b`. Its later [fresh 7715 one-pass run](../policy-crash-7715/README.md) passed. The original first-run script SHA is recorded in `manifest-original.txt`.

`selected-native.json`, `native-operations.json`, and `native-artifact-hashes.txt` are bounded keyless evidence. The exact first and second InvocationIDs are in `controller-identity.txt`; the final continuation unit was stopped by its separately verified description/InvocationID and ended inactive/MainPID0. No private keys, Store, or binary call contents were copied here. Owner unit 7001 and hosted units 7801/7803 were untouched.
