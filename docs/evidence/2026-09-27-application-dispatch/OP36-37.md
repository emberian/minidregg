# Private dispatch authoring source gate

Stdio op36 prepares a detached dispatch signing plan from a strict canonical
request and a refreshed verifier-minted persistent session. Op37 takes the
strict plan and ordered detached signatures and assembles canonical ingress
for op34. The source helper is human-origin only; agent dispatch needs a
separate authoring path. These operator/custodian-private operations do not
admit a request or mint a committed delivery permit. Op34 rechecks the entire
assembled ingress against the then-current verified Mini image.

`author application-dispatch-request` accepts a strict JSON object with
`issueIndex`, `ticketResource`, `packageManifest`, `snapshotManifest`, three
observe-capability selectors, and exact HTTP `operationId`, method/path/query,
ordered headers, and body. Binary values use lowercase hex. `inspect
application-dispatch-request` and `inspect application-dispatch-plan` return
the exact canonical request bytes; the latter also gives source-derived
app/session/subject/principal/permission bits, current image boundary, and all
ordered invocation plus observation signing headers. The inspection is a
custody challenge presentation, not an authorization decision. Inspector
binary input is bounded at 12,102,760 bytes; compact JSON at 96,822,080.

`Host.Json` then `Host.Main` compiled serially, exit 0, in the independent
writable `/home/ember/build/minidregg-dispatch-inspect-overlay` with one Lean
process, `LEAN_NUM_THREADS=2`, `MemoryMax=64G`, and `CPUQuota=200%`. The
overlay imported source-matched read-only OLeans from the committed dispatch
snapshot and copied the certified custody `Host.Json` OLean as a plain file
