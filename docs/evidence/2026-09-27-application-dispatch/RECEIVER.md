The warm API is `receiveVerified config (old : NativeHostReplay.Verified config target) bytes`. `old.issues` is the prior-issue context minted during the native verified walk or retained by exact extension. Each request decodes the strict full wrapper, calls `admitDispatchVerified` for fresh current native checks, and submits that same typed `DispatchAt.intent`. It does **not** call `ApplicationDispatchUpper.admit` or redo full replay per HTTP request. Cold process open, restart, or an externally appended suffix needs `verifyLoaded`/persistent session refresh before this API. After exact success, `permit.verified = extendExact old readback` is the new warm state.
