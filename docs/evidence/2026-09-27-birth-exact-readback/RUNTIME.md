# Copied-Store birth receiving comparison

The retained r3 first-workroom ordinary birth call (212,637 bytes, SHA-256 `1ff9d4ad41644a376884d13a6092787a2ca6a2a7d99c30659263f04221d8bdb7`) was submitted only to separate mode-0700 private Stores on hbox. Each Store was initialized by the pinned SQLite helper's `publish` from retained `genesis.bin`. The canonical readback SHA-256 was `6a3e5c8a128d5737c2165bdd94d5e8795553896219121029c66fbdb1bd752ef2`; the physical SQLite file SHA-256 was `8ce7e8e82cfd7b750bbfdebff10e477479212d253e2e02ae11f5117a183b4b29`, both identical to the original genesis evidence. Only `storageRoot` changed in each private config, except for the explicitly marked transport-fault trials. No live r3 Store or count-27 image was used or changed. The archived r3 tree has no count-18 physical snapshot, so this experiment establishes the ordinary birth path at genesis, not the growing-history cost of the count-19/21/23/25 births.

The pinned SQLite helper ELF SHA-256 was `9a5054813d9ad358ece337b99121cb37a36ba82b4b92ad0e287dcc7e529190e0`. The private commands were `minidregg-link-sqlite-store-9746c47 publish PRIVATE_STORE genesis.bin`, followed by `read-to PRIVATE_STORE readback.bin` and exact byte/hash comparison before submission. No authorization field of the copied config changed.

The baseline is certified `cb55b81` Host ELF SHA-256 `89973efe154b3f53bb279a931a93aed0b0a1d341d759dc776dca635dda01c354`. The candidate is exact `2721253` Host ELF SHA-256 `f62c716885d8f9258750da70113afc8d4086907a2cdbc1c11a8a5e3c5043bdcd`, built from its committed source with 353/353 Lean modules and affected native C/link passing; manifest SHA-256 `ad982d1ff97d352af38d1a1d8bbebebb3f5144d2c9b1737e5c0c11405ee45156`. The candidate was not installed into the live service.

`runtime/base/birth-stdio-probe.rs` is a test-only frame carrier. It sends the unchanged canonical signed call as stdio opcode 2, reads the complete framed outcome, then sends the same call as receipt-only opcode 3 on the same Host process. It does not encode or reinterpret the signed call or an intent. The runs were sequential, each with a 900-second bound; their raw `/usr/bin/time -v` outputs and source-inspected typed outcome JSON are retained under `runtime/`.

For each `stdio-*` directory, the exact invocation shape was `cd PRIVATE_DIR && /usr/bin/time -v timeout 900 ../base/birth-stdio-probe HOST_ELF config.json ../base/call.bin . host.stderr > probe.stdout 2> probe.stderr`, substituting the certified baseline or candidate ELF above. Source inspection used that same Host's `config.json inspect outcome outcome.bin outcome.json` and the analogous `lookup.bin`. Direct CLI controls used `timeout 900 HOST_ELF config.json submit ../base/call.bin outcome.bin`; cold read-only replay used `timeout 600 CANDIDATE_ELF config.json lookup ../base/call.bin cold-lookup.bin`. These exact commands and exit codes appear in the bounded raw stderr files.

As a cold-path control, direct CLI `submit` on two more copied genesis Stores returned the same outcome and physical Store bytes in 2:48.76 baseline versus 2:44.24 candidate. Direct CLI `submit` does not call `submitVerifiedLoadedWith`, so this pair does not measure the new exact-readback path. Cold replay still performs historical native validation; unchanged warm-session lookup is the 0.408-second case above.

Private deterministic transport probes exercised fallback behavior without changing the signed call:

- `birth-cas-uncertain.sh` maps one CAS to the SQLite helper's `cas-crash … after-commit`. Candidate op2 returned `confirmed/recoveredAfterUncertainResponse` with the same four receipt fields after exact physical readback; same-session op3 was `confirmed/replayed`. The post-Store hash remained `e5515e15…`.
- `birth-readback-stale.sh` performs the real CAS, then substitutes the original canonical genesis bytes for exactly one post-CAS `read-to`. Candidate op2 returned `uncertain`, rather than promoting an exact verified tip. The next same-session op3 refreshed from the actual Store, re-admitted the recorded birth, and returned the original `confirmed/replayed` receipt. Its lookup SHA-256 and physical Store hash matched the normal candidate. This run took 76.941 seconds for op2 and 74.663 seconds for recovery op3.
- `birth-already-present.sh` performs the real CAS, then forwards the helper's second `AlreadyPresent` observation for the identical bytes. Candidate op2 returned `confirmed/installed` with the same outcome bytes and post-Store hash, and same-session lookup returned the original receipt. This deterministically tests the equal-byte `AlreadyPresent` branch; it is not a dual-process concurrency stress test.

The `runtime/` bundle contains only bounded timing output, typed receipt/outcome projections, and test transport source. It omits the signed call, config, private keys, full Store, and binaries. A separate private measurement-only cb55 binary (SHA-256 `71092ab5…`) was built with phase timers, but was not run after the decisive paired result; its timings are not part of this evidence. The live r3 service remained on its existing Host throughout.
