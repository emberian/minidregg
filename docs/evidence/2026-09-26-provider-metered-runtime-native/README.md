# Native provider metering: bounded results

These are projections from **separate fresh private Mini Stores** on Persvati. They do not contain Store histories, keys, request bodies, or complete Hermes transcripts. The positive and missing-usage runs used immutable runtime commit `1c56596` (Linux ELF SHA-256 `b584a93755e6fbcdaf352a3522909a7f2a90426824bb3bc69559e644adcd400b`), Host op19 SHA-256 `51f790fa55f734772c37330dc0ab7408f3438d4e168b74bd6432d0b1cdb111f6`, Mini client SHA-256 `fee5bc861d74c9e432db2374ede36b62852a80346a46f1dc89133dfa79bf11eb`, and fake provider SHA-256 `9dcf21258716ccae9f9c70cd91e7ef9ecd78ad714d480d9abae071e5366041fd`. Runtime release nextest passed 42/42. The tariff was 1 micro-unit per input or output token and signed provider reserve was 3.

`positive-*` captures a real 37,069-byte Hermes completion request, one upstream completion, retained 775-byte SSE response and 96-byte raw response headers, a source-authored [meter report](positive-meter.json) with 1 prompt + 2 completion tokens and charge 3, and an exact [confirmed Mini settlement outcome](positive-settle-outcome.json) at accepted count 11. The [signed provider view](positive-signed-view.json) reports status 1, remaining 47, reserved 0. The [journal projection](positive-journal-projection.json) retains the exact charge, meter identity, settlement call/outcome hashes and receipt, while provider hold and attempt are cleared. This establishes a completed local fake-provider settlement, not a paid-model charge.

`missing-usage-*` captures a separate real 37,069-byte completion request and one upstream response whose 571-byte SSE body omitted terminal usage. [Native Host refusal bytes](missing-usage-refusal.bin) say `SSE completion lacks one terminal usage record`. The [journal projection](missing-usage-journal-projection.json) retains the confirmed reserve 3 and received response, with no meter report, settlement, or provider replay. The upstream log has one completion even after Hermes retry. This is a held, unresolved effect, not a zero-charge settlement.

The first HTTP 422 candidate did **not** test 422: Hermes sent a 1,466-byte auxiliary title-generation request through the same provider lease first. Its attempt was retained as `uncertain:prompt lease revoked during provider send`, with zero upstream completions. The [bounded journal projection](auxiliary-collision-journal-projection.json) and [log excerpt](auxiliary-collision-log-excerpt.txt) preserve that liveness finding. It neither proves a 422 response nor an unauthorized send. Runtime source permits a later sequential request after exact successful settlement and retains exact response replay, but that multi-request path has not yet passed a native gate. Here the cancelled auxiliary left an unresolved hold, which correctly blocked the main request. The generated scoped Hermes profile lacks an auxiliary-request purpose policy; optional auxiliary calls need explicit restriction or independently reserved, metered handling.

A subsequent fresh private Store ran the committed `2a42440` runtime (Linux ELF SHA-256 `1e0b384618561a809ecf2b23a7f957d73ceba382908f6ed74f1eadd80a76a4ef`) with title generation explicitly disabled in the scoped Hermes profile. Its 37,069-byte main request reached the fake upstream once and received HTTP 422. The [native refusal](http-422-refusal.bin) says `provider HTTP status is not 200`; the [journal projection](http-422-journal-projection.json) retains `received:422:application/json` and confirmed reserve 3, with no quote, replay, or settlement. The [upstream log](http-422-upstream.log) contains one `metered-422` entry. Two earlier fixture setup attempts in this same Store failed before worker/provider reserve because the private workspace/key and then a stale control socket were absent; their outputs remain private and are excluded from this receiving verdict.

Another fresh Store with that same immutable `2a42440` runtime exercised **three sequential provider requests in one Hermes prompt**. The [upstream log](multi-upstream.log) records read (37,069 bytes), publish (38,194 bytes), and final completion (40,189 bytes), each exactly once. The three source-authored [meter reports](multi-read-meter.json), [publish meter](multi-publish-meter.json), and [completion meter](multi-complete-meter.json) each retain usage 1+2, reserve 3, charge 3 over distinct exact request/response digests. Mini [read settlement](multi-read-settle-outcome.json), [publish settlement](multi-publish-settle-outcome.json), and [completion settlement](multi-complete-settle-outcome.json) are separate confirmed transactions at accepted counts 11, 15, and 23. The [journal projection](multi-journal-projection.json) retains three exact response replays and no provider hold or attempt; the [signed final provider view](multi-final-signed-view.json) reports generation 5, remaining 41, reserved 0. The driver stopped after the third settlement, before claiming a completed whole Hermes conversation. This proves sequential request accounting in one prompt, not concurrent-provider liveness.

The projections keep private `/tmp` paths solely to identify the original retained files. `SHA256SUMS` fixes every copied artifact's bytes. No live hosted Store or controller was changed by these runs.
