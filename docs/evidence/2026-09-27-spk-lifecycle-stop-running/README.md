# Verified running-incarnation STOP source check

An app at serving phase 4 has a running START unit from its current generation `g`. STOP advances the app operation to `g+1`, but must fence that existing unit. The earlier launch author incorrectly set STOP `processIdentity` to the new `g+1` unit, which made a truthful stop audit of the running unit fail V2 report validation.

This source cut leaves historical V2 `ApplicationLifecycleResidentProfile.beginMatches` unchanged and adds `beginMatchesV3`: STOP expects the prior-generation unit; INSTALL/START continue to expect the new operation-generation unit. The v3 BEGIN author signs STOP with operation generation `g+1` and prior unit `g` only after `Verified.selectRunning` selects a certificate from the current verified replay.

`NativeHostReplay.PriorRunningV3` is constructed solely after an event25 `.running` completion is natively admitted at its original prefix, its entire intent record matches, and the successor validates. The list is newest first. STOP selects the latest running completion for the app, checks its original generation equals the current serving generation, and checks its unit, image, and exact record are present in the verified prefix. `BeginV3History.stop` retains this witness. Event25 STOP admission separately requires its report's unit, invocation ID, control group, and volume custody to equal those of the selected running completion. The STOP operation generation remains `g+1`; it is never used as a unit selector.
