Persvati, 2026-09-26. [Raw safe evidence](CONTROLLER-CRASH-2026-09-26.log) SHA-256 `d4d7111fbc063fceadde0716e67c38a37761430bc66741b34e0ced03b28b9627`. This used a fresh private Mini deployment: parent task 7401, tool 7402, publication 7403, certified selected-bbf Host SHA `775a98c704e98b8a3065b2a93e9659aacf8f731f31d38b6360607e6bce64af19`, and the immutable Linux `grain-runtime` binary SHA `8126b3432c56b040219ef53436a740f123813ee3658888663aa0f0e3df78ff30` built from committed recovery source main SHA `28bb49e187964f1606433f6d51cec5154b4fe9e07cb68194d2981b16a73eaa27` and MCP SHA `03b4963831f44a77b9b4051dac98f86ef1dbe30a1cf2662d565b5bcc23a08ef4`. The log records launcher, gate, config, bootstrap and one-off probe hashes. It did not touch the earlier SSH task or shared fn state.

After a signed hard attach and reservation, a held worker ran in transient unit `mini-grain-t7401-o6.service`, bound to the active `mini-grain-controller@7401.service`. Its cgroup contained three captured host PIDs and its durable gate said `started`. SIGKILL targeted **only the controller MainPID**. systemd's `BindsTo` relationship stopped the worker; its unit became inactive with MainPID 0, its cgroup emptied, and all captured PIDs were absent or zombies. The gate remained `started` and the journal retained the child marker and three-unit hold, so a replacement controller could not mistake process disappearance for a completed operation.

The same-name controller restarted with the same private config and state. A fresh attach was refused while the task was unresolved. `recover` durably fenced the exact gate, audited that unit and cgroup empty, wrote a machine-proven `recover-gated-worker` reconciliation entry, and only then cleared the child marker. Signed Mini readback showed generation 2, status 5, remaining 97, reserved 3. The parent hold and external-effects notices stayed present. A separate private admin action audited zero-charge settlement; signed readback returned generation 2, status 0, remaining 100, reserved 0. Explicit external-effects acknowledgement then cleared the notices. No replacement worker launched during recovery.

This run exercised the case where systemd stopped the worker immediately after controller death. The separate [deployed-source launch-gate race probe](../../docs/evidence/2026-09-26-host-session/launch-gate-linux-deployed-race.log) covers a delayed transient `ExecStart` arriving after a durable fence; this crash run did not depend on a surviving orphan. The private signed attempts and views remain under `/tmp/mini-grain-crash-20260926` with hashes in the raw log.
