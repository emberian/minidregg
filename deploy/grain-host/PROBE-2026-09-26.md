# Persvati containment probe, 2026-09-26

Host: `persvati`, Linux `6.17.0-40-generic`, systemd `257`; uid 1000 has a
running user manager, `/usr/bin/systemd-run`, `/usr/bin/bwrap`, and
`/proc/sys/kernel/unprivileged_userns_clone = 1`. All probes used temporary
files below `/tmp/mini-grain-*` and uniquely named transient **user** units.
They were removed after the run. No shared unit files, privileges, fn node, or
Mini build lane were changed.

systemd manager. Its unedited output is in `PROBE-2026-09-26.log`. The final
run used launcher SHA-256

and probe SHA-256

The raw log includes the host cgroup paths and PIDs observed before each
stop, then the inactive unit result.

1. A transient service ran a shell that started `setsid sleep 15`. The
   descendant appeared in the service cgroup. `systemctl --user kill
   --signal=SIGKILL --kill-whom=all UNIT.service` left its host PID absent and
   the unit failed/stopped.
2. A `bwrap` namespace with only `/usr`, `/dev`, `/proc`, `/tmp`, and a
   dedicated workspace mounted could execute a shell but could not see a
   sibling scratch secret.
3. A copy of this launcher executed a fixed `/agent/probe` in a transient
   service with `--network none`. It printed `worker-ok` and exited with
   `SUCCESS`.
4. A worker launched through this wrapper started a `setsid sleep 30`.
   Before `TERM` to the wrapper, the host cgroup contained PIDs
   `2662723,2662747,2662748,2662749`. After the wrapper trap killed the unit,
   all four host PIDs were absent and the unit was inactive. An initial probe
   mistakenly read an in-namespace PID from the worker, which can name an
   unrelated host process; the corrected check used the host
   `/sys/fs/cgroup/.../cgroup.procs` file.
5. The final launcher version passed `bash -n`, ran the no-network worker,
   and rejected a workspace mount that contained `MINI_GRAIN_STATE_DIR` and
   `MINI_GRAIN_CUSTODY_KEY` with exit 77.
6. After adding a second kill/stop check for a unit creation race, the final
   launcher stopped host PIDs `2680812,2680813,2680814,2680815` from a
   `setsid` worker and observed the unit inactive.
7. A Unix socket from the controller directory was visible inside the worker
   only at `/run/mini-grain.sock`; the controller key path remained absent.
   Supplying a host config under `/usr` was rejected with exit 77 before the
   unit started.
8. A worker bound with `BindsTo=mini-grain-controller@2715625.service` lost
   all four host cgroup PIDs (`2715651` through `2715654`) when that transient
   controller service stopped. The worker unit became inactive.

These observations establish local cgroup membership and stop of a
`setsid` descendant on this host. They do not yet establish the full Mini
controller-to-launcher hard disconnect path, crash recovery, provider network
policy, or separately bootstrapped user custody. Those depend on the runtime
unit-handle integration and a deployed Mini task.
