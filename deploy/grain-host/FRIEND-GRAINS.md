# Offering a Mini grain over SSH

This is the operator path for a friend to enter one already-provisioned Mini resource grain. A persistent `grain-runtime serve` owns the private Mini custody key and process journal. The friend receives an SSH key whose forced command connects only to that task's private control socket. The friend does not receive the Mini host operator key, controller key, tool key, admin socket, or a shell command option.

The operator first installs a source-matched Mini host, `mini` client, SQLite store, signature verifier, `grain-runtime`, `bwrap`, compiled sibling `launch-gate`, and `grain-ssh` at fixed absolute paths. `launch-gate` must be compiled from this directory's Rust source on the Linux target. Keep the Mini host and its storage/operator credentials under a separate operator account. A task account needs only access to the host socket and its own task custody files; Mini still checks every signed intent, current generation, capability and allowance. Use a different Unix task account for unrelated friends or grains so one account cannot read another task's controller state.

Provision the Mini resources through the native author/bootstrap/birth/delegate flow in `native/grain-runtime/acceptance.sh`, using a version that has passed the current host and controller-ownership checks. A historical frozen acceptance script predates the transient-unit ownership safeguard and must not be reused for onboarding. Retain the signed attempts, pinned host config, and queried task pages. Create separate parent and tool tasks and narrow named read/publication grants for each object the tool may touch. The current fn coordination route consumes a Mini-exported, independently verified package, renders a Lean-authored provenance article, then signs and posts it through fn's isolated coordinator; it is not a grain-registration API or a source of Mini authority. Do not give fn posting credentials to the worker.

For each task, place the runtime JSON at `/opt/mini/grains/TASK.json`, owned by its dedicated task account and mode 0600. Its `stateDir` is an owned real directory at mode 0700; `controlSocket` is directly inside it. Store `custodyKey` and any tool/provider custody files outside all worker bind roots. The runtime's `admin.sock` remains inside this directory and is never an SSH forced-command target. The fixed `hermes-acp` command uses `systemdScope:true`, the `bwrap` launcher, a nonsecret immutable runtime root, and a task workspace as its only writable host mount. The launcher verifies the sibling gate protocol, blocks controller secrets in mounts, and starts one bounded transient user service per operation.

Run `mini-grain-controller@TASK.service` under that task account's `systemd --user` manager. As that account, use [`install-controller`](install-controller) to render and install a direct instance unit for an already-provisioned runtime JSON and operator-selected executable SHA-256 pins. The installer checks file ownership, private state and keys, pinned executable bytes, the launcher/gate protocol, and unit name conflicts. Its pins identify the artifacts the operator selected; they are not a certificate that those artifacts came from a particular source revision. It does not bootstrap Mini resources, validate signed policy, or start the service. See the [installer example](README.md#controller-unit-installation) for its exact inputs. Enable linger if the controller must survive logout, then explicitly enable/start the unit. Verify the control socket exists, the journal has no unresolved hold, and the queried native task page matches the intended task and budget before issuing a friend's key. Restarting the service must use the same config and private state; replacing a journal-bound command in place is refused.

Put one line per friend's public key in the task account's `authorized_keys`, with a fixed task socket and attachment mode. For example, with only the public key text substituted:

```text
restrict,command="/opt/mini/bin/grain-ssh /opt/mini/bin/grain-runtime /var/lib/mini/grains/task-7001/control.sock hard" ssh-ed25519 AAAA... friend-hard
```

`render-friend-key ABS_GRAIN_SSH ABS_RUNTIME ABS_CONTROL_SOCKET hard|soft FRIEND_PUBKEY` validates a live socket and one Ed25519 public key, then prints this line without modifying `authorized_keys`. Review the line and install it only for that task account.

Use `soft` instead of `hard` only when the friend intentionally wants a running operation to continue after SSH disconnect. The forced command ignores `SSH_ORIGINAL_COMMAND`; the `restrict` key option disables forwarding, PTY, agent forwarding and user rc. Keep password login disabled for this task account and do not grant the friend another unrestricted key. The friend enters with `ssh -T TASK_ACCOUNT@HOST`. The wrapper waits for the signed Mini attach acknowledgement before reporting readiness. A hard SSH EOF physically stops the owned worker unit, fences the Mini generation, and retains uncertain allowance for audited reconciliation; soft EOF detaches the display while the controller and bounded worker continue. A reconnect uses the same durable controller, not a new one-off `serve` process.

An operator handles a crashed or uncertain worker through the private admin socket and signed Mini readback, including an explicit external-effects acknowledgement where required. The friend forced command exposes neither admin mode nor the host operator key. Do not clear a child marker or start a replacement worker based only on a PID: the durable gate must be fenced, the exact systemd unit and cgroup audited empty, and the native held amount reconciled. Keep gate tombstones while operation IDs may be reused.

Before onboarding, run the source-coupled gate race probe and the native grain acceptance in private scratch, then test the actual SSH forced command against a dedicated test task. Retain source/binary hashes, signed Mini views, unit/cgroup observations, and ACP/MCP receipts. Provider egress and keys require a separate deployment decision; `--network host` reaches host services, while `--network none` has no network access.
