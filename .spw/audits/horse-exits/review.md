# Exit-path review

This bounded pass traced whole executable definitions at durable append/receipt, launch and dispatch handoff, selected fn publication, protected-object encrypted custody, local current-source verification, credential service, and private backend WAL/burn cuts. Exact source spans and hashes are in provenance.json. The SQLite Store publication source was later compared with authoritative integration SHA and matches; its sibling anchor definitions were read remotely. This is not a completed system audit.

The concrete restart counterexample is an advertised initial Host SHA followed by a crash, pathname replacement, and unvalidated restart. The initial checked-fd patch was integrated, then strengthened with an immutable sealed Linux successor. It copies source bytes to executable memfd, seals writes/growth/shrink and additional seals, then hashes the sealed snapshot and executes that same retained image. Two exact-production-helper tests pass: different image rejected on restart; seals deny writes/truncate and replacing or rewriting original bytes between check and exec still runs the original snapshot. Common resource-client composition and receiving startup remain captain work. The non-Linux path still launches a checked pathname. Linux adds one executable-sized anonymous memory image per Host lifetime, copied only on launch/restart, with no per-request cost.

The rotation counterexample was real in the observed common source, but it already had an owner repair. After accepted rotation, old code installed daily, then NEXT, deleted staged AFTER, then updated workspace/result; interruptions could make the next command select a new epoch and changed signing secret. The owner authored an active operation pointer, immutable successor material and idempotent exact installation, qualified against native lost-submit-response handling. Common had only helper publication, so the captain was notified to import the actual wired consumer. Do not count owner-source success as common-source success.

Mental execution confirms the key acknowledgment cuts read: CAS must match exact entry on readback; uncertain recovery cannot manufacture fresh physical permits; source historical receipts remain available across current authority changes; selected fn POST markers prevent blind repost after lost responses; protected-object ciphertext/package material is saved before release; private WAL returns exact outboxes only after fsync. These are source facts under their documented physical premises. Local archives and backend reference request_delivery do not establish fresh native release authority.

No live worlds, services, Store data, private assets or external messages were changed. No broad builds were run. Tests used isolated synthetic executable fixtures.

The expanded pass read whole provider external-send, outcome recording and delivery methods plus Mini child cancellation, dispatch RPC deadline cuts and lifetime reverse client success validation. The provider gateway spools exact requests before curl, registers the child under its active lease gate, fsyncs upstream response files, and waits for controller Outcome plus source metering before downstream reply. Local delivery has a separate bridge ACK and caches exact response before settlement. Cancellation before child creation is a definite no-spawn; cancellation after creation preserves uncertainty even when the client child is killed. Terminal completion is a presentation projection and cannot turn retained uncertain/review state into completed.

An error-taxonomy concern remains open: controller answer_dispatch maps all dispatch_rpc errors to refused, including errors after possible custody mutation. The reviewed lifetime reverse consumers require exact success frames and keep conservative recovery, so this pass did not demonstrate an unsafe retry or cleared hold from that classification. This is an open interface question, not a proven bug.

The SQLite anchored prefix joins the retained-session optimization explicitly: unchanged sibling anchor binds deployment/genesis and exact retained last entry (height/record/tag) through SHA. BEGIN IMMEDIATE plus INSERT-only append checks current head, commits, then fsyncs/renames the new anchor and fsyncs its parent before Installed. Same-height replacement with a different last entry fails against unchanged sibling custody. The anchor is not a recomputation of all earlier records; immutable prefix depends on the honest SQLite/native API premise and unchanged anchor custody. Simultaneous Store+anchor replacement or arbitrary earlier-entry writes violate that physical premise. Generic Transport carries no proof of it.
