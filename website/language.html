Objective Bend

Objective Bend is Mini's authored language. Its model is François-René Rideau's (Faré's) account of objects: lazy open recursion over first-class, partial, composable specifications.

The language computes. Mini supplies what the language does not: durable identity, current authority, effect admission, funding and controlled disclosure.

Core4

The core calculus is called Core4. It is the Term type in Theory/ObjectiveBendOpenRecursion.lean, and it has these parts:

  • Laziness. The reference semantics is call-by-name. The machine is call-by-need: an argument becomes a shared heap thunk, evaluated at most once. Laziness is part of the meaning, not an optimisation: {good = 7, bad = self.bad}.good is 7, and an unused divergent argument is never forced.
  • Specifications. A specification is a first-class partial extension C → V → W: given the final self and the inherited super, it produces a new value. It is a value before any target exists.
  • Mixins and fixpoints. mix(lower, upper) = λself. λsuper. upper self (lower self super) composes two layers under one final self. fix(spec, inherited) closes the knot, and it is a computation, not an equation.
  • Prototypes and reflection. A prototype pairs a specification with its target. reflect, metadata and project take one part without forcing the other.
  • Records and sums. Records hold each field as a separate suspension; extend overrides fields. Sums have lazy injections, case and a Boolean branch.
  • Activities. An activity yields a typed Plan with perform and is resumed with a typed response. Effects are part of the type, and the checker never lets an effect sit inside a shared thunk.
  • Types and quantities. The checker is proof-producing: it returns a typing derivation for the actual term. Quantities are erased, affine, linear and unrestricted; affine and linear are both checked as at most once, not exactly once.

The front end, which turns .obend source into Core4 terms, is written in TypeScript. It is a named trusted boundary: no theorem relates the source text to the core term.

Specifications and late binding

Billing calls self.price, so it sees a surcharge that a later layer adds. Nobody edits Billing.

```sh
$ bun docs/tutorial/run.ts docs/tutorial/ch4-specs.obend billOfTwo
status: finished
type: Nat
result: 7

$ bun docs/tutorial/run.ts docs/tutorial/ch4-specs.obend surchargedPriceOfTwo
status: finished
type: Nat
result: 8

$ bun docs/tutorial/run.ts docs/tutorial/ch4-specs.obend surchargedBillOfTwo
status: finished
type: Nat
result: 9

Without Surcharge, bill(2) is 7: the price is 6 and the fee is 1. With it, the price is 8 and the bill is 9.

An activity

serve asks its host to move a counter from count to count + 1, then asks again after every response. It never finishes; each response resumes it once.

$ bun docs/tutorial/run.ts docs/tutorial/ch8-counter.obend serve '["0"]' '["written","written","refused"]'
status: yielded
type: Activity<sum {write: {field: Nat, before: Nat, after: Nat}}, sum {written: {}, refused: {}}, Nat>
turn 1: yield write({field: 0, before: 0, after: 1})  <- written({})
turn 2: yield write({field: 0, before: 1, after: 2})  <- written({})
turn 3: yield write({field: 0, before: 2, after: 3})  <- refused({})
turn 4: yield write({field: 0, before: 2, after: 3})  (waiting)
diagnostic: waiting for a response

Turn 3 is refused, so the count stays 2 and turn 4 asks for the same write again. These responses are typed in by hand: the preview stands in for the kernel and admits nothing. No kernel delivers responses to an activity or stores its checkpoint yet.

What is not proved, and what is not wired

  • The proofs are not in the default build. At main, the Objective Bend proof modules are imported only by an opt-in research library, so a green default build re-checks none of them.
  • Front-end adequacy. No theorem relates .obend source to the core term. The TypeScript parser and elaborator are trusted and checked only by replay.
  • A resource bound for completeness. Completeness gives finite completion, not a bound on the limits that suffice.
  • Linearization. Declared ancestry (spec S extends A, B) is linearized with C4 by the elaborator; the invariance statement is stated and not proved.
  • Quantities at run time. Use counts are checked statically only.
  • Native admission. On main, no Objective Bend source has produced a native accepted receipt. The admission modules compiled in lanes and are being integrated. On that path, the caller still chooses the work it is charged for, and zero work means free execution up to the policy maximum.
  • Studio's preview route. On main the Rust side and the TypeScript side speak different preview wire versions, so the route is broken; the tools run directly.

What you will meet quickly

  • No -, <, >, <=, >= or /: they parse and are refused at elaboration. Subtraction is written by recursion.
  • A match on a Nat takes exactly a zero case and a successor case; a match on a sum has no wildcard.
  • requires is carried as a string and never checked. Spec laws are closures that nothing discharges.
  • before and after methods are refused.
  • Plans and responses must be non-recursive data, so a view library waits.
