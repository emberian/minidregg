# Grain terminal presentation

`grain-runtime terminal /absolute/task/control.sock` presents one existing Mini grain controller as a simple text conversation. The default attachment is **hard**: closing the terminal while a worker runs invokes the controller's existing hard disconnect and Mini generation fence. `grain-runtime terminal /absolute/task/control.sock soft` explicitly chooses the existing soft detach rule, under which the bounded worker may finish after the terminal closes. This command opens only the task control socket. It does not read custody keys, the private admin socket, or the controller journal.

Type a prompt as ordinary text after the controller reports `ready`. The terminal sends it through the same `hermes PROMPT` controller path as the raw connector. While it runs, another ordinary line is refused locally rather than silently passed to the controller's busy loop. `/status` asks for a bounded presentation state when idle; while busy it reports the last known busy state. `/new` selects the existing `conversation new` command, `/recover` selects existing `recover`, and `/quit` closes the connector. EOF uses the same hard or soft detach rule as `/quit`; piped input EOF can interrupt a still-running hard attachment. Native Mini remains responsible for every reserve, publication, settlement, fence, and exact recovery lookup.

The terminal control protocol is opt-in: its first socket line is `attach terminal-v1 hard` or `attach terminal-v1 soft`. Each controller display chunk, including untrusted ACP/model text, is serialized as a JSONL `output` frame with its text escaped. The terminal renders that text with a `│` prefix on every line and visibly escapes cursor, color, and direction controls; a model can still *say* a status-like sentence, so the prefix distinguishes model prose from controller events. Input lines, frames, and the local event queue are bounded; oversized data is refused without truncation. Controller-authored `state` and `prompt-complete` frames are separate queue variants and carry the current attachment ID and request ID; a late completion from a detached terminal is dropped. `state` exposes only `ready`, `busy`, or `review-needed`, whether a Hermes session is retained, and a review flag. It does not expose the full `status` journal, paths, keys, attempt records, or signed receipts. A completion error is never labeled successful; the operator must use the existing private admin and signed Mini evidence for uncertain transitions. Status is a display projection, not a native admission or receipt.

The raw `grain-runtime connect SOCKET [hard|soft]` protocol and existing `grain-ssh` forced-command wrapper remain available for scripts and deployed keys. An operator may pin the new terminal command in a separate task-specific forced-command entry after validating the binary and socket ownership. The terminal does not select a different task or widen the operator's configured publication/read allowlists.
