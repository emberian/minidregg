# Member-authored worlds and shared programs

The shell supports member-authored kind definitions, retained instance descriptors, map fields, immutable programs, ROM method bindings, and current kind-export restrictions. Run the source hooks in this order on a fresh source-matched after-core fixture:

1. `journey.d/jworld-kind.sh`: kind creation, signed shared read, instance construction, old descriptor retention, and current exported law.
2. `journey.d/jworld-method.sh`: member poll method, exact free-quota boundary, explicitly funded compute, refused funding without debit, and retained retry.
3. `journey.d/jworld-board.sh`: twelve sparse natural task identities, independent member edit, reuse of the same poll program to count tasks and close the board, and refusal after closure.
4. `journey.d/jworld-prototype.sh`: a finite immutable library bundle, shared final self dispatch, inherited super calls, exact sample/output comparison, retained retry, and current kind-law refusal.

Use the existing journey environment: `MINI HOST CONFIG SOCKET SPONSOR_WS NEWCOMER_WS NEWCOMER_SUBJECT JOURNEY_STEP_DIR`. Bootstrap the dedicated Store with `NEWPARTICIPANT_OWNER_BUDGET=1000000000000`; the newcomer must have zero admitted compute usage for its day before the method hook. Do not share a running Store with another fixture. The method hook installs an initially invalid tariff through the sponsor's factory-management capability and reads each new instance before preparing edits. Retained calls use `retry ID`, preserving their original intent.

Board and prototype hooks default their output directories beneath `JOURNEY_STEP_DIR`; each refuses an existing directory. The board hook consumes the method hook's actual registered `wm-close` program and funded `wm-payer` reference. The prototype helper authors canonical nouns and jam bytes only; the real source evaluator executes them. For Nock opcode 2, a literal selector formula must be quoted before evaluation.

The board example establishes arbitrary keyed data and shared program reuse. It does not yet impose a generic per-task status transition law. The prototype example establishes shared self/super execution, with a client-authored finite closure. Authenticated programs constructing new kind definitions from observed world prototypes remain a separate kernel increment.
