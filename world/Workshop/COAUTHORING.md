# A reusable coauthoring institution

`CoauthoringInstitution.bend` lets a community propose a published revision,
endorse it once per electorate principal, close an exact decision, and prepare
adoption against the current source and native roots. The same institution can
govern station rules, fictional canon or a technical community tool. Its scope
is explicit; a fictional persona is a credit, never a real principal, electorate
identity, editor grant or payment account.

The institution consumes the existing `CollectiveAdoption.Proposal`, `Ballots`,
`CastResult`, `Resolution` and `Installation`. An `Offer` supplies scope, logical
source export and author credit around that one ballot image. Receiving must bind
it to the existing authenticated ballot resource. It must not maintain another
ballot image or private proposal journal. Source and activity live in ordinary
native module documents and append resources mounted by Studio.

A submission requires the exact charter policy, a proposer principal, attribution
to the actual invocation actor, a strictly advancing revision, a valid electorate
and an exact candidate found through the composed catalog callback. The library
then delegates endorsement uniqueness, round binding, quorum and exact decisions
to `CollectiveAdoption`. It derives counts from retained ballots; no passed count
or narrator endorsement becomes a decision.

Closing and preparing adoption also require the current charter editor and exact
policy. Adoption calls the composed reviewer, then the existing current-base,
prototype, kind-root, instance-root and migration checks. The returned installation
remains a proposal to native receiving; editorial status does not grant install,
source-read or payment authority.

`WorldCoauthoring.VersionRef` keeps the full reviewed candidate and logical export
separate. Candidate program identity is not an export label. The native package
producer must bind the declaration to its actual source module/export. Station's
continuing authored catalog can consume this reference to invite a rule revision,
show the decision and keep the old authored version visible.

Existing consumer instances retain their own source pins. Adoption changes the
default for fresh instances; migration is an explicit separate governed operation.
The source returns the exact old pin declarations unchanged. The actual native
lowering must keep those resource IDs outside the mutation footprint and use the
existing immutable ROM-pin law. This source property alone does not prove native
instance preservation.

`CoauthoringFaces.bend` supplies a working face with individually admitted source,
proposal, decision, history and pinned-instance slots, plus independently prepared
propose, endorse, decide, adopt and fresh-instance intents. Its source/activity
face reuses `WorldSurface.source_face`. There are no authored enabled bits,
private journal copies or special institution renderer handlers.

These modules are authored WIP, shipped before qualification. Their filled general
laws cover exact offered version/export, exact delegation of the whole cast
result, unchanged pin declarations, principal/persona separation and no activity
on refused transitions. New module source/Book checks and composition remain
unrun. They introduce no native endpoint or alternative evaluator.

The next receiving join needs current admitted actor/charter/ballot/source images,
the exact published package/export, and shared typed Plan lowering that atomically
consumes the predecessor and appends the corresponding activity. Installation
also needs actual current native authority, disjoint old-instance mutation
footprints, source retention and recovery without repeated effects or charges.
Private results use the current audience/read law; cryptographic privacy requires
the separate bound encryption relation.
